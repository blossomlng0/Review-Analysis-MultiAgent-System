# Review-Analysis-MultiAgent-System
# 💄 LangSmith 기반의 실시간 고객 리뷰 인사이트 플랫폼 구축

> **KT AIVLE School 2차 미니프로젝트 (23조)**
> * **진행 기간**: 2026.05.11 - 2026.05.13 (3일)
> * **주요 역할**: 조장 / State 관리자
> * **사용 기술**: Python, LangChain, LangGraph, LangSmith, Streamlit, SQLite3, OpenAI API

<br>

## 📌 1. 프로젝트 개요 (Project Overview)
이커머스(KT 쇼핑라운지)에 입점한 뷰티 브랜드(뷰엘라 코스메틱스)의 대규모 화장품 리뷰 데이터를 대상으로, **속성 기반 감성 분석(ABSA, Aspect-Based Sentiment Analysis)을 수행하는 Multi-Agent 시스템**을 구축했습니다. 

단순한 키워드 추출을 넘어 보습력, 향, 발림성 등 화장품 특유의 속성별로 소비자의 긍·부정 감정을 정교하게 분류하고, 이를 **Streamlit 대시보드로 시각화**하는 동시에 **LangSmith를 통해 LLM 파이프라인을 실시간 모니터링 및 최적화(LLMOps)**하는 안정적인 AI 인프라를 구현하는 것이 본 프로젝트의 목표입니다.

<br>

## 🛠️ 2. 핵심 수행 내용 및 결과 (Key Deliverables & Results)
* **Supervisor 기반 Multi-Agent 아키텍처 설계**: LangGraph를 활용하여 상태(State)를 공유하고 복잡한 리뷰 분석 프로세스를 유연하게 제어하는 에이전트 시스템 구현
* **DB 배치 처리 및 안정화**: SQLite3 데이터베이스에 누적된 고객 리뷰 데이터를 효율적으로 처리하기 위해 Batch 예측 프로세스 구축
* **실시간 LLMOps 모니터링 인프라**: LangSmith 레이어를 연동하여 전체 에이전트의 실행 Trace를 추적하고 프롬프트 성능, 비용(토큰 사용량), 실행 속도 최적화
* **인사이트 시각화 대시보드 웹 서비스**: Streamlit을 활용하여 입점 업체가 상품의 장점과 개선점을 속성별로 한눈에 파악할 수 있는 대시보드 UI 구현

<br>

## 🚨 3. 문제 상황 및 해결 과정 (Troubleshooting)

### ❓ Problem: 다중 에이전트 환경의 DB 잠금(Lock) 및 대기 시간 지연
1. **DB 동시성 충돌**: 복수 에이전트가 동시에 SQLite 데이터베이스에 접근하여 분석 결과를 업데이트하거나 상태를 변경하는 과정에서 **`sqlite3.OperationalError: database is locked` 이슈가 발생**했습니다.
2. **분석 병목 현상**: 수많은 리뷰를 한 건씩 순차적으로 LLM에 요청함에 따라 API 호출 오버헤드와 실행 시간이 기하급수적으로 늘어나는 성능 저하 문제가 존재했습니다.

### 💡 Solution: 트랜잭션 제어 및 Batch 처리를 통한 최적화
1. **DB 동시성 제어 및 예외 처리**: 데이터베이스 커넥션 풀 및 트랜잭션 격리 수준을 조정하고, 충돌 발생 시 안정적으로 재시도할 수 있는 예외 처리 로직을 코드 레벨에 반영하여 잠금 현상을 원천 해결했습니다.
2. **배치(Batch) 예측 아키텍처 도입**: 단건 호출 방식에서 탈피하여 DB에 쌓인 데이터를 적정 단위로 묶어 처리하는 Batch 프로세스를 설계함으로써 LLM 호출 효율성을 대폭 극대화하고 처리 시간을 감소시켰습니다.

<br>

## ✨ 4. 차별점 및 배운 점 (Our Strengths & Lessons Learned)

### 🏃‍♂️ 우리 조만의 차별성
* **엔지니어링 관점의 시스템 고도화**: LLM의 프롬프트 튜닝에만 집중하는 방식에서 벗어나, 데이터 분산 및 공유를 담당하는 **State 관리자 역할**을 주도하며 시스템 아키텍처 완성도에 집중했습니다.
* **철저한 LLMOps 기반의 디버깅**: 에이전트의 오작동 및 예외 케이스 발생 시, **LangSmith의 실행 Trace 가시화 기능**을 적극 활용하여 어느 노드(Node)에서 병목이나 에러가 발생하는지 정밀 추적하고 프롬프트를 화장품 도메인에 맞춤형으로 디버깅했습니다.
* **실질적 비즈니스 가치 창출**: 가공된 데이터를 단순 텍스트가 아닌 실제 화장품 입점 브랜드가 상품 기획 및 부정 리뷰 대응에 바로 활용할 수 있도록 **속성별 필터링 기능이 포함된 실시간 대시보드** 형태로 서빙했습니다.

### 🧠 배운 점
* LangGraph 구조 안에서 전역 상태(State)를 안정적으로 관리하고, Supervisor 노드가 하위 에이전트를 조율하는 반복 제어 메커니즘을 확실하게 체득했습니다.
* 프로덕션 환경의 LLM 서비스를 운영하기 위해서는 LangSmith와 같은 모니터링 도구를 통한 비용/속도 추적과, 백엔드 데이터베이스의 동시성 제어 및 대용량 데이터 배치 처리가 필수적임을 깊이 이해했습니다.
